# Research: an assistant that adds an event by asking about it

**Date**: 2026-10-29. **Sources**: DeepSeek's API documentation, its Open Platform terms and privacy
policy; Render's documentation; this repository and the public API of the live site. No call to
the model was made: what only a call can tell is listed at the end.

## R1. The model

- **Served**: `deepseek-flash` and `deepseek-v4-pro`; the older `deepseek-v4-flash` is still
  accepted and served by Flash.
- **Price per million tokens, `deepseek-flash`** (off-peak / peak): input found in the cache
  $0.003 / $0.006, input not in the cache $0.15 / $0.30, output $0.60 / $1.20. Peak hours are
  01:00-04:00 and 06:00-10:00 UTC, Monday to Friday.
- **Billing is prepaid.** A call is paid from the account's balance; an empty balance answers
  402 "Insufficient Balance". The balance is a hard cap, which is what the site requires of a paid
  provider (the voice chat was removed for lacking one).
- **Thinking is on by default.** `"thinking": {"type": "disabled"}` (or `reasoning_effort: "none"`)
  turns it off. In thinking mode `temperature` has no effect and a required or named `tool_choice`
  answers 400. Default `max_tokens`: 8K without thinking, 64K with it.
- **JSON output**: `response_format: {"type": "json_object"}` guarantees valid JSON; the prompt must
  contain the word "json" and should show the shape; the API "may occasionally return empty
  content", and too small a `max_tokens` cuts the JSON off.
- **Tool calls** are supported. A schema-enforced ("strict") mode exists in beta only: base URL
  `https://api.deepseek.com/beta`, `strict: true` on every function, every property required,
  `additionalProperties: false`, no `minLength` / `maxLength` / `minItems` / `maxItems`.
- **Cache**: automatic and best-effort, by common prefix; an unused entry is cleared "usually within
  a few hours to a few days".
- **Usage in every reply**: `prompt_tokens` (= `prompt_cache_hit_tokens` +
  `prompt_cache_miss_tokens`), `completion_tokens`, `completion_tokens_details.reasoning_tokens`.
  Enough to count tokens per admin (decision 8) without asking anything else.
- **Limits**: 2500 concurrent requests per account for Flash, 429 beyond; a request that has not
  started within 10 minutes is closed; while it waits, a plain request receives empty lines and a
  streamed one `: keep-alive` comments. A `user_id` field ([a-zA-Z0-9-_], up to 512) gets limits of
  its own.
- **Images**: Flash accepts them, so a poster could be read. Not asked for; noted only.

Proposed for the plan, from the above:

- Thinking off: a turn is a question and a few fields, not a puzzle, and thinking multiplies the
  output tokens and the wait.
- JSON output rather than strict tools (beta), the server checking every field itself: the model's
  reply is untrusted input whatever mode produced it.
- What never changes (instructions, skills, the lists of types and disciplines) first in the
  prompt, so the cache serves it at a fiftieth of the price.
- **An estimate, not a measurement**: about 8 turns an event; about 6K input tokens a turn, 4-5K of
  them from the cache; about 6K output tokens in all. That is roughly $0.006 an event off-peak and
  $0.012 at peak. The first real calls replace it with numbers.

## R2. Data and the terms

- **Open Platform terms** (released 2026-04-22, effective 2026-04-29):
  - 4.2: the customer keeps their rights in the inputs and is assigned the outputs; no clause was
    found that lets DeepSeek train on them (the terms were read through a summarizing tool, not
    line by line);
  - 3.3: the customer tells its end users how their personal information is processed, and has
    their consent or another legal basis;
  - 5.5: the relevant privacy policy is disclosed to end users;
  - 8.1: "You shall clearly disclose to your end users that the Output content is generated by AI".
  - The terms say nothing about where API data is stored or for how long.
- **DeepSeek's privacy policy** (updated 2026-02-10) covers its own apps and websites. It stores
  personal data in the People's Republic of China and lists training as a purpose, with an opt-out.
  It says the processing of end users' data collected by an API customer is outside it.
- Proposed: the site's privacy policy says what goes to a language model (decision 19 leaves the provider unnamed);
  the chat says plainly that it is an AI assistant (8.1). A published announcement carries no
  mark (decision 20).

## R3. The server

- gunicorn 26 with `threads = 4` runs the threaded worker. Its main loop keeps up the heartbeat
  while a thread waits, so a long call to the model does not get the worker killed.
- Render runs `WEB_CONCURRENCY=1`: four threads for the whole site, of which the thumbnail service
  may hold two. A call to the model holds one thread for as long as it lasts.
- Render's own limit on a request: not in the documentation found; posts on its forum say
  100 minutes. It does not bind here.
- Proposed: short turns (no thinking, small replies, the long texts written once the facts are
  gathered and again only on request); a timeout of our own on the call, so a hung one frees its
  thread; no streaming in the first version, the reply being JSON for the form. To be revisited on
  the first measurements.

## R4. The key on Render

- Dashboard: the service, then **Environment**, then **+ Add Environment Variable**. "Save only"
  keeps it for the next deploy; "Save and deploy" redeploys the current build; "Save, rebuild, and
  deploy" builds anew.
- The settings read the environment through django-environ, `env("NAME", default="")`, as they do
  for `INDEXNOW_KEY`.
- Proposed: without the key the chat is not offered, so development and CI never reach the model.
- Whether DeepSeek's dashboard splits spending by key was not found in its documentation. The site
  counts tokens per admin itself (decision 8), so a key of the site's own is for revoking it alone;
  the maintainer issued one (decision 17), and the site counts nothing for now. One account is one balance: the assistant and the agents pay from the same
  money unless the site gets an account of its own.

## R5. The form, the page and the place

- **The form** (`SubmitCompetitionForm`):
  - titles, descriptions and the link preview in ru / kk / en (only the Russian title required);
    a description is HTML in a hidden input written by a Quill editor;
  - event types and disciplines, both multiple: 6 types and 91 disciplines in 12 directions on the
    live site;
  - a depth-4 venue, or a new venue: city, name in three languages, latitude and longitude;
  - the start and end dates; links and files (announcement, registration, route, regulations,
    results); the preview image; "invite only"; the admin's top-event mark;
  - registration's settings, on the same page.
  - There is no start-time field: the time is in the text, by the maintainer's choice.
- **Quill 1.3.7**: the static `Quill.find(container)` gives the editor; text goes in through
  `clipboard.dangerouslyPasteHTML`. So the model's HTML is passed through the site's own
  `sanitize_rich_html` (`cycling_site/sanitize.py`) on the server first; otherwise a script in it
  would run in the admin's browser.
- **The place cascade** (`_location_cascade.html`) holds the whole tree in the page but keeps its
  functions in a closure. A venue can be chosen from outside only through a small hook there; one
  that does this already exists inside, `selectExistingVenue(pk)`.
- **The tree is too big for a prompt**: 1650 places, 440 KB as JSON from `/api/v1/locations/`.
  Proposed: the model names the place in words and the server finds it. It can reuse:
  - the agents' pure helpers: `agent/locations.py` (`match_city`) and `agent/venues.py`
    (`same_place`);
  - the geocoder in `instagram_agent/geo.py` (`locate`, one request a second);
  - a track's first point from `agent/geo.py` (`start_coordinate`, `parse_start`, behind the
    public-address guard).

## R6. Repository rules that shape the folder

- Skills written in Russian need a line in the `no-non-ascii` hook's `exclude`
  (`.pre-commit-config.yaml`), as the agents' guidance files have.
- The model's name is checked by the `llm-model` CI job, which reads `DEFAULT_LLM_MODEL` from
  `agent/config.py`. The assistant either uses that constant or the check learns to read the
  assistant's.
